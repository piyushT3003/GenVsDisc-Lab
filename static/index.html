Head-to-head

Both were trained on the same 60 000 MNIST images. The classifier spends all its capacity on drawing boundaries between classes, so it classifies better. The CVAE spends its capacity modelling the whole image — which lets it generate, reconstruct and judge typicality.

Two ways to model the same data

Discriminative
p(y | x)

Learns the decision boundary. Given an image, outputs a probability for each label. Cannot create images.

Generative
p(x | y) · p(y)

Learns how the data is distributed. Can sample new images, and can still classify through Bayes' rule.

How the models in this app work

  1. Preprocessing. Your drawing is converted to MNIST format: inverted if needed (white ink on black), cropped, scaled to fit 20×20 and centred by centre of mass in a 28×28 frame.
  2. Classifier. Conv(16) → ReLU → MaxPool → Conv(32) → ReLU → MaxPool → Dense(128) → Dense(10) → Softmax.
  3. CVAE encoder. Image + one-hot label → 512 → 256 → (μ, log σ²) of a 2-D latent z.
  4. CVAE decoder. z + one-hot label → 256 → 512 → 784 pixel probabilities.
  5. Generation. Sample z ~ N(0, I), choose a label, decode → a new digit that never existed.
  6. Generative classification. Compute ELBO(x, y) for y = 0…9, add log p(y), softmax → p(y | x).

Experiments to try

  • Classification vs generation: draw a clean “7”. Both models agree — but only the generative one can then produce new 7s.
  • Ambiguous digit: draw something between a 4 and a 9. Compare how the two probability bars split.
  • Out-of-distribution: scribble or draw a letter “A”. The classifier still picks a digit, often confidently; the typicality meter drops.
  • Model inference: compare inference times — one pass for the classifier vs 10 encode/decode passes for the generative model.
  • Temperature: in Generator Studio raise the temperature to 2.5 and watch the classifier agreement fall.
  • Latent space: look where your digit lands on the style map — neighbouring cells share its slant and thickness.
